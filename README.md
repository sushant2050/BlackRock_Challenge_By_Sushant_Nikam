# BlackRock_Challenge_By_Sushant_Nikam
BlackRock Challenge by Sushant Nikam
🐳 Deployment (Docker)As per the challenge requirements, the application is containerized to run on a Linux-based distribution.Build the ImageThe first line of the Dockerfile includes the specific build command requirement:Bashdocker build -t blk-hacking-ind-{name-lastname} .
Run the ContainerThe container exposes and maps port 5477 as required:Bashdocker run -d -p 5477:5477 blk-hacking-ind-{name-lastname}
🛠 API EndpointsThe system is organized into three primary functional modules:1. Transaction ValidatorEndpoint: POST /blackrock/challenge/v1/transactions:validatorValidates a list of transactions against wage and investment ceilings. Returns categorized lists of valid, invalid, and duplicate transactions.2. Temporal Constraints ValidatorEndpoint: POST /blackrock/challenge/v1/transactions:filterFilters transactions based on specific periods (q, p, and k). Each period applies distinct rules (e.g., "fixed" or "extra" amounts) that determine transaction validity.3. Returns CalculationEndpoints: * POST /blackrock/challenge/v1/returns:npsPOST /blackrock/challenge/v1/returns:indexCalculates investment returns using variables including age, wage, inflation, and investment breakdown by "k" periods.📈 Problem LogicThe core "Self-saving" strategy uses an auto-saving strategy with multiples of 100.Input Constraints: Supports up to $n < 10^6$ expenses.Rounding: For each expense, the system calculates the "remanent" to reach the next hundred-multiple to determine the investable amount at the end of the year.
